# Stable files and editable projects

This module independently reads stable `osu file format v12`, `v13` and `v14`, `Mode: 2`, and writes v14. It does not call a lazer encoder. Other input versions and unsupported object types are rejected.

- `OsuBeatmapReader.Read(text, sourcePath)` / `ReadFile(path)` returns a `MapDocument`. Original sections, timing line order, same-time points, hit samples, slider paths/repeats and spinner lines are retained. Video/storyboard text is retained but not loaded or rendered.
- `OsuBeatmapWriter.Serialize(document, compensateTinyDroplets)` returns text, a parsed `ReadBack`, diagnostics and quantization/reconversion errors. `WriteFile` atomically writes after validation and reconversion, and refuses the imported source path. Legacy Sliders and spinners retain their original lines; modified fruit keeps its original flags, Y and sample suffix.
- FSliders become linear-path sliders with their authored `SpanCount`; nodes, generated path and pixel length describe the first span. A converted Legacy Slider keeps its original flags, hitsound and samples while its edited geometry is re-encoded. Changing span count preserves head/tail and remaining repeat edge samples, assigns defaults to new edges, and reports the adjustment.
- New or edited integer coordinates/times use midpoint-away-from-zero rounding. Output parent order uses current precise times before rounding, preserving order when times collapse. Reconversion verifies source identity, event index, kind and order, including repeat fruits and ticks, not just equal counts. If `ObjectSequenceMatches` is false, converted error values are NaN and diagnostics explain that a positional comparison is unavailable.
- A changed generated SV replaces the green points at its rounded head with one effective green point, retaining the red point and effective sample metadata. The original SV is restored at integer head + 2 ms only when a Legacy Slider needs that speed before the next original timing point or generated head. Otherwise SV continues to that boundary without an unused restoration point; each generated head uses the emitted state to establish its required SV. Conflicting same-time Legacy Sliders, FSliders requiring different SV, a rounded head crossing a BPM boundary, and boundaries too close for safe SV changes are rejected. Timing lines outside replaced green points keep their relative order and spelling.
- Integer path quantization can change cumulative length and the actual stream. The original intended pixel length remains explicit; the imported-path implementation performs length adjustment. The report measures the resulting objects instead of substituting target positions.
- `ProjectSerializer` uses schema version 1 JSON and preserves IDs, original source context, editable curve handles, per-anchor outgoing segment kinds, span counts, per-track Tiny compensation overrides and inherited NaN timing metadata. Older projects without the new fields default to one span and inherited segment/compensation settings. The referenced Catch conversion still generates ticks for inherited NaN. Lists are restored rather than discarded. Unknown schema/fields and invalid model values are rejected. File saves use temporary files; relative audio/source paths resolve against the project location. Project saves also refuse the imported `.osu` source path.
- `.osu` audio references must stay within the beatmap directory; absolute, drive, network and parent-traversal paths are rejected. Projects may refer to local parent directories but reject UNC resource paths. The App owns resource copying and `.osz` extraction; these Core APIs do not copy or execute resources. A changed audio selection updates `AudioFilename` on export; unchanged subdirectory references are preserved.

The format fixture harness includes independent timing/sample/curve cases and optional external v14 maps extracted under `artifacts/beatmaps`; invocation and fixture requirements are in [Testing](../../../docs/TESTING.md). It checks unedited real-map object/timing preservation and project round trips. Export timing tests calculate duration directly from emitted length, span count, beat length, SliderMultiplier and SV without using the production reader. They check exact and +1 ms lookup scenarios and integer-truncated timing offsets.

## Sources

- [Official `.osu` format specification](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_%28file_format%29): sections, field types, slider span count, sample syntax and inherited timing.
- [LegacyBeatmapDecoder.cs](https://github.com/ppy/osu/blob/48c4800e3ae4ee752452cdff83bd3787ccf3105f/osu.Game/Beatmaps/Formats/LegacyBeatmapDecoder.cs): legacy timing and difficulty decoding, including inherited NaN.
- [LegacyBeatmapExporter.cs](https://github.com/ppy/osu/blob/48c4800e3ae4ee752452cdff83bd3787ccf3105f/osu.Game/Database/LegacyBeatmapExporter.cs): stable-compatible export floors control-point times, motivating integer restoration offsets that cannot collapse onto the slider head. This timing fix uses independently implemented logic; this MIT-licensed file was consulted as a reference, not copied.
- [ConvertHitObjectParser.cs](https://github.com/ppy/osu/blob/48c4800e3ae4ee752452cdff83bd3787ccf3105f/osu.Game/Rulesets/Objects/Legacy/ConvertHitObjectParser.cs): v12–v14 coordinates pass through float then integer truncation. The reader preserves original spelling separately from this interpreted value.
- [Conversion references](../Conversion/UPSTREAM.md): the shared actual Catch conversion and imported path implementation, its fixed revisions, limits and MIT notices.
